# Админка — дизайн

Веб-админка `apps/admin` (React + Vite + TanStack Router + Tailwind v4, иконки `lucide-react`). Те же токены, что и в мобилке, но плотнее: это рабочий инструмент оператора на десктопе. Доступ — только роль `ADMIN`, проверка на сервере.

Эталоны: `reference/screens/*.html` (открыть в браузере, ширина 1440) и `reference/png/*.png`. Спецификации разделов — в `sections/`.

## Зачем админке именно эти разделы

Анализ рынка (подробнее — [`../market-research.md`](../market-research.md) и раздел «Источники» ниже) даёт пять выводов:

1. **Админку недооценивают.** Модерация, управление пользователями, споры и аналитика нужны с первого дня, а не «потом».
2. **Метрика номер один для молодого маркетплейса — ликвидность:** доля заявок, нашедших исполнителя, и время до совпадения. Это важнее числа скачиваний. Поэтому на дашборде — «Заявки с откликом» и «Первый отклик».
3. **Ручная проверка документов** — очередь с таймером ожидания, чек-лист критериев, решение «одобрить / отклонить / запросить заново» с причиной и запись в журнал.
4. **Споры** решаются, когда оператор видит обе стороны, переписку, оплату и срок решения на одном экране.
5. **Журнал действий** нужен для честности решений: кто, когда, что и почему. Это доказательство при споре о бане.

## Общие правила

- **Всё необратимое — с причиной.** Бан, отклонение верификации, скрытие отзыва, решение спора, скрытие из каталога: причина обязательна (пресеты + комментарий), запись в журнал, push пользователю с причиной.
- **Подтверждение** нужно только для бана, решения спора и удаления справочника. Остальные действия — сразу, с тостом «Готово» и кнопкой «Отменить» на 5 секунд.
- **Документы верификации** открываются по временной ссылке (10 мин), не скачиваются кнопкой, каждый просмотр пишется в журнал. В пет-проекте — только тестовые изображения.
- **Персональные данные в списках маскируются:** телефон `+7 701 ••• •• 47`, полный номер — только в карточке по клику «Показать» (тоже в журнал).
- **Четыре состояния** у каждой таблицы: загрузка (скелетон строк), пусто («Ничего не найдено» + «Сбросить фильтры»), ошибка (Banner danger + «Повторить»), нет сети.
- **Фильтры в URL** (`?status=DISPUTED&page=2`), чтобы ссылку на выборку можно было открыть заново; плитки дашборда ведут в списки с готовыми фильтрами.
- **Клавиатура:** `⌘K` — поиск; в очереди проверки `J`/`K` — следующий/предыдущий; фокус-кольцо 2 `trust` на всём интерактивном.
- **Только светлая тема** в MVP (токены `.dark` уже есть в `tailwind-theme.css`, если понадобится).

## Токены в коде

Заменить плейсхолдеры в `apps/admin/src/styles/index.css` блоком из [`../tokens/tailwind-theme.css`](../tokens/tailwind-theme.css). Классы: `bg-bg`, `bg-surface`, `bg-surface-2`, `text-ink`, `text-ink-2`, `text-ink-3`, `border-border`, `bg-action text-on-action`, `bg-brand text-on-brand`, `text-brand-text`, `bg-trust-tint text-trust`, `bg-success-tint text-success`, `bg-warning-tint text-warning`, `rounded-md` (12), `rounded-lg` (16), `font-display`. Сейчас в `SideNav.tsx` используются `bg-primary-soft text-primary` — заменить на `bg-surface-2 text-ink` + риску.

## Чего нет в MVP (фаза 2)

Рассылки push из админки, выплаты специалистам, роли «модератор» и «поддержка» с разными правами, PRO-подписки, автоматическая модерация. Каркас меню оставляет место для них в группе «Настройки».
