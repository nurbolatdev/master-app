# Приёмка экрана

Экран считается сделанным по дизайну, когда все пункты отмечены. Скопируйте список в описание задачи/PR.

## Сверка с эталоном

- [ ] Открыт эталон `reference/png/screens/<экран>.png`; скриншот реализации (390×844, светлая тема) совпадает по расположению блоков, отступам и размерам (допуск ±2 dp).
- [ ] Шрифты: Unbounded только там, где в спеке `title`/`price`/`display`; остальное — Inter нужного начертания.
- [ ] Цвета — только из `theme.ts`; в коде экрана нет hex, `rgba`, «магических» чисел для отступов и размеров.

## Темы и размеры

- [ ] Тёмная тема проверена (сверка с `reference/png/screens/08-specialist-feed-dark.png` по токенам).
- [ ] Экран на 360 и 430 dp ширины: ничего не обрезано, нет горизонтального скролла.
- [ ] Системный шрифт 130%: текст переносится, кнопки растут, ничего не перекрыто.

## Поведение

- [ ] Все 4 состояния: загрузка, пусто, ошибка, нет сети.
- [ ] Нажатия дают отклик; сетевые действия показывают loading в кнопке.
- [ ] Safe area сверху и снизу; контент не уходит под таб-бар и CTA-панель; клавиатура не перекрывает поле.
- [ ] Не больше одной кнопки `brand` на экране.

## Доступность

- [ ] Тач-цели ≥ 48 dp, зазор ≥ 8.
- [ ] У иконок-кнопок есть `accessibilityLabel`; роли и состояния выставлены.
- [ ] Статусы не только цветом — иконка + текст.
- [ ] Скринридер читает экран в визуальном порядке.

## Тексты и данные

- [ ] Все строки в i18n, ru и kk.
- [ ] Деньги, расстояния, даты — через общие форматтеры (`patterns.md` §5).
- [ ] Приватность: телефон мастера не показан до принятия заказа; точная позиция мастера не показывается вне статуса «В пути».
